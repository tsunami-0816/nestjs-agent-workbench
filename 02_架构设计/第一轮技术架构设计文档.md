# 第一轮技术架构设计文档 · nestjs-agent-workbench

> 第 2 步产物，基于 `01_项目基线说明书.md` 产出。
> 普通模式，不含前端设计方向小节（R24）。

## 1. 技术选型说明

| 层 | 选型 | 版本 | 选择理由 | 兼容性说明 |
|---|---|---|---|---|
| 运行时 | Node.js | 20 LTS | JD 要求 Node.js；20 是当前 LTS，原生支持 ESM/stable fetch | Docker 用 `node:20-alpine` 基础镜像 |
| 后端框架 | NestJS | 10.x | JD 核心要求；Module/Controller/Service/Guard 分层是面试必讲点 | 最新稳定版，与 @nestjs/typeorm 兼容 |
| 语言 | TypeScript | 5.x | JD 要求 TS；NestJS 原生支持 | strict 模式开启 |
| ORM | TypeORM | 0.3.x | NestJS 官方集成 `@nestjs/typeorm`；Active Record + Data Mapper 双模式 | 与 MySQL 8 兼容 |
| 数据库 | MySQL | 8.0 | 共用基础设施 3310；JD 要求 MySQL | database=`nestjs_workbench` |
| 缓存 | ioredis | 5.x | Redis 客户端；JWT 黑名单用 SET EX；热对话缓存 | 共用 6379，db=6 |
| 认证 | @nestjs/jwt + @nestjs/passport + passport-jwt | 最新 | NestJS 生态标准 JWT 方案 | Access Token 有效期 2h |
| 密码哈希 | bcrypt | 5.x | Node 原生 bcrypt；10 轮 salt | 不依赖 Python passlib，无兼容问题 |
| DTO 校验 | class-validator + class-transformer | 最新 | NestJS 原生 Pipe 集成；M8 指标要求 | 全局 ValidationPipe 开启 whitelist |
| WebSocket | @nestjs/websockets + @nestjs/platform-ws | 最新 | 用 ws 原生库而非 socket.io，更轻量、面试好讲"原生 WebSocket 协议" | 前端用原生 WebSocket API，无需 socket.io-client |
| 大模型 SDK | openai | 4.x | DeepSeek 是 OpenAI 兼容接口，直接用 openai SDK 改 baseURL | `baseURL: https://api.deepseek.com`，`model: deepseek-chat` |
| 前端框架 | Vue 3 + `<script setup>` | 3.4+ | JD 要求 Vue3；Composition API | Vite 构建 |
| 前端语言 | TypeScript | 5.x | 前后端全 TS | |
| UI 库 | Element Plus | 2.x | b2b-admin 默认组件库；登录表单/对话框/菜单齐全 | 普通模式用默认主题 |
| 状态管理 | Pinia | 2.x | Vue3 官方推荐 | 存 token + 当前用户 |
| 路由 | Vue Router | 4.x | 前端路由 + 守卫 | |
| 构建 | Vite | 5.x | 前端 dev server 5183 | |
| 容器编排 | Docker Compose | v2 | 起 backend + frontend 两容器；MySQL/Redis 用共用基础设施 | 不重复起 MySQL/Redis 容器 |

**明确不用**：socket.io（用原生 ws）、TypeORM 的 QueryBuilder 过度封装（简单查询用 Repository）、Redis 集群（单实例够用）、Prisma（JD 没提，TypeORM 更 Spring Boot 风格好讲）。

## 2. 整体分层架构

```
┌─────────────────────────────────────────────────┐
│  接入层  Vue3 前端 (Vite dev :5183 / Nginx prod) │
│         ├─ REST 调用 (axios)                     │
│         └─ WebSocket 长连接 (ws://:8089/ws)      │
└──────────────────┬──────────────────────────────┘
                    │ HTTP / WSS
┌──────────────────▼──────────────────────────────┐
│  应用层  NestJS (:8089)                           │
│  ├─ AuthModule     注册/登录/JWT/黑名单           │
│  ├─ ConversationModule  对话 CRUD                 │
│  ├─ MessageModule  消息历史分页                   │
│  ├─ ChatGateway    WebSocket 流式对话             │
│  ├─ HealthModule   健康检查                       │
│  └─ AdminModule    admin 用户列表（路由级 RBAC）   │
├───────────────────────────────────────────────────┤
│  服务层  Service 业务逻辑                         │
│  ├─ AuthService    bcrypt 校验 + JWT 签发         │
│  ├─ ConversationService  CRUD + Redis 缓存        │
│  ├─ MessageService  消息持久化 + 分页             │
│  ├─ ChatService     DeepSeek 流式调用编排          │
│  └─ JwtBlacklistService  Redis SET/GET 黑名单    │
├───────────────────────────────────────────────────┤
│  存储层                                           │
│  ├─ MySQL 8 (共用 :3310)  database=nestjs_workbench│
│  │    └─ users / conversations / messages         │
│  └─ Redis 7 (共用 :6379)  db=6                   │
│       ├─ jwt:blacklist:<jti> → "1" EX 2h          │
│       └─ conv:list:<userId> → JSON 最近10对话 TTL 5min│
├───────────────────────────────────────────────────┤
│  外部依赖  DeepSeek API (https://api.deepseek.com)│
└───────────────────────────────────────────────────┘

运维层：docker compose up backend+frontend；MySQL/Redis 依赖共用基础设施容器
```

**每层职责：**
- **接入层**：Vue3 SPA，负责渲染、WebSocket 连接管理、token 存储（localStorage）
- **应用层**：NestJS Module 边界，每个 Module 导出自己的 Controller/Service/Gateway，跨模块通过 Service 注入
- **服务层**：纯业务逻辑，不处理 HTTP/WS 细节；ChatService 编排"调 DeepSeek 流→写库→推 WS"
- **存储层**：TypeORM Repository 操作 MySQL；ioredis 直接操作 Redis
- **外部依赖**：DeepSeek API 用 openai SDK，stream=true 逐 chunk 读取
- **运维层**：Docker Compose 只起 backend+frontend；MySQL/Redis 是本机共用容器

## 3. 核心业务链路

### 链路 A：注册 → 登录 → 拿 JWT

```
前端 POST /auth/register {username, password}
  → AuthController.register
    → AuthService.register:
        1. 查 users 表 username 是否已存在（409 if exists）
        2. bcrypt.hash(password, 10)
        3. INSERT users (username, password_hash, role='user')
    → 返回 {id, username, role}

前端 POST /auth/login {username, password}
  → AuthController.login
    → AuthService.login:
        1. SELECT * FROM users WHERE username=?
        2. bcrypt.compare(password, user.password_hash)
        3. 不匹配 → 401
        4. JWT sign: {sub: userId, username, role, jti: <uuid>}, expiresIn: '2h'
    → 返回 {access_token, user: {id, username, role}}

前端 localStorage 存 access_token，后续 axios 拦截器自动加 Authorization: Bearer <token>
```

### 链路 B：WebSocket 流式对话（核心链路）

```
前端 new WebSocket('ws://localhost:8089/ws?token=' + token)
  → ChatGateway.handleConnection:
      1. 从 query.token 解析 JWT
      2. 查 Redis jwt:blacklist:<jti> → 存在则 close(4001)
      3. 校验通过 → 连接成功，存 client map: userId → ws

前端发送: {type: "chat", conversationId: "123", content: "你好"}
  → ChatGateway.handleMessage(data, client):
      1. 从握手用户态取 userId（已在连接时鉴权）
      2. 校验 conversationId 属于当前 userId（SELECT conversations WHERE id=? AND user_id=?）
      3. 写 user 消息到 messages 表
      4. 调 ChatService.streamChat(conversationId, content):
         a. openai.chat.completions.create({
              model: 'deepseek-chat',
              messages: [{role:'user', content}],
              stream: true,
            })
         b. for await (chunk of stream):
              - 提取 delta.content
              - ws.send({type:'chunk', conversationId, messageId, content: delta.content})
         c. 流结束 → 拼 fullContent → INSERT messages (role='assistant', content=fullContent)
         d. ws.send({type:'done', conversationId, messageId, fullContent})
         e. 失效 Redis 缓存 conv:list:<userId>（下次查库回填）
      5. 异常 → ws.send({type:'error', message: e.message}) + close
```

### 链路 C：对话列表 + 消息历史

```
前端 GET /conversations
  → ConversationController.findAll
    → ConversationService.findAll:
        1. 查 Redis conv:list:<userId>
        2. miss → SELECT * FROM conversations WHERE user_id=? ORDER BY updated_at DESC LIMIT 10
        3. 回填 Redis EX 300s
    → 返回 [{id, title, updated_at}]

前端点对话 → GET /conversations/:id/messages?page=1&size=20
  → MessageController.findHistory
    → MessageService.findHistory:
        1. 鉴权：conversation.user_id === 当前 userId
        2. SELECT * FROM messages WHERE conversation_id=? ORDER BY created_at DESC LIMIT 20 OFFSET 0
        3. 反转为时间正序返回
    → 返回 [{id, role, content, created_at}]

前端刷新页面 → 重新 GET /conversations → 历史仍在（M4）
```

### 链路 D：登出

```
前端 POST /auth/logout（带 Bearer token）
  → AuthController.logout
    → AuthService.logout:
        1. 从 req.user 取 jti
        2. Redis SET jwt:blacklist:<jti> "1" EX 7200（与 token 过期时间一致）
    → 返回 204

后续带旧 token 请求任意接口 → AuthGuard 查黑名单命中 → 401（M5）
```

## 4. 数据模型设计

### users 表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT UNSIGNED | PK, AUTO_INCREMENT | |
| username | VARCHAR(50) | UNIQUE, NOT NULL | 登录名 |
| password_hash | VARCHAR(255) | NOT NULL | bcrypt hash |
| role | ENUM('user','admin') | NOT NULL DEFAULT 'user' | RBAC 角色 |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | |

### conversations 表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT UNSIGNED | PK, AUTO_INCREMENT | |
| user_id | INT UNSIGNED | NOT NULL, FK→users.id, INDEX | 所属用户 |
| title | VARCHAR(100) | NOT NULL DEFAULT '新对话' | 首次对话后可改为首条消息前20字 |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 最后一条消息时间 |

### messages 表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 消息量大用 BIGINT |
| conversation_id | INT UNSIGNED | NOT NULL, FK→conversations.id, INDEX | |
| role | ENUM('user','assistant') | NOT NULL | 谁发的 |
| content | MEDIUMTEXT | NOT NULL | 消息内容（长回答用 MEDIUMTEXT） |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP, INDEX | 分页排序用 |

**索引设计**：
- `idx_conversations_user_updated ON conversations(user_id, updated_at DESC)` — 列表查询
- `idx_messages_conv_created ON messages(conversation_id, created_at DESC)` — 历史分页
- `uk_users_username ON users(username)` — 注册查重

**关联**：conversations.user_id → users.id（多对一）；messages.conversation_id → conversations.id（多对一）。不做外键约束（TypeORM synchronize 模式下用逻辑外键 + INDEX，避免删用户时级联锁表）。

## 5. 接口规范

### 统一响应格式

成功：
```json
{ "code": 0, "data": {...}, "message": "ok" }
```

失败：
```json
{ "code": 401, "message": "未登录或token已过期", "traceId": "uuid" }
```

### 错误码

| HTTP 状态码 | code | 含义 |
|---|---|---|
| 200 | 0 | 成功 |
| 400 | 400 | 参数校验失败（DTO 错误信息在 message 里） |
| 401 | 401 | 未登录/token 失效/被黑名单 |
| 403 | 403 | 已登录但角色不够 |
| 404 | 404 | 资源不存在 |
| 409 | 409 | 用户名已存在 |
| 500 | 500 | 服务器内部错误 |

### 鉴权规则

- 公开接口：`POST /auth/register`、`POST /auth/login`、`GET /health`、WS 握手（token 走 query 不读 header）
- 其余所有 HTTP 接口必须带 `Authorization: Bearer <jwt>`
- AuthGuard 全局注册，用 `@Public()` 装饰器豁免公开接口
- AdminGuard 加在 `/admin/*` 路由上，校验 `req.user.role === 'admin'`

### 核心接口清单

| 方法 | 路径 | 鉴权 | 请求体 | 返回 data |
|---|---|---|---|---|
| POST | /auth/register | 公开 | {username, password} | {id, username, role} |
| POST | /auth/login | 公开 | {username, password} | {access_token, user:{id,username,role}} |
| POST | /auth/logout | 登录 | — | 204 空 |
| GET | /conversations | 登录 | — | [{id, title, updated_at}] |
| POST | /conversations | 登录 | {title?} | {id, title, created_at} |
| GET | /conversations/:id/messages | 登录 | ?page=1&size=20 | [{id, role, content, created_at}] |
| GET | /health | 公开 | — | {status:"ok", uptime} |
| GET | /admin/users | admin | — | [{id, username, role, created_at}] |

### WebSocket 消息协议

连接：`ws://localhost:8089/ws?token=<jwt>`

客户端→服务端：
```json
{ "type": "chat", "conversationId": "123", "content": "你好" }
```

服务端→客户端（流式 chunk）：
```json
{ "type": "chunk", "conversationId": "123", "messageId": "456", "content": "你" }
```

服务端→客户端（完成）：
```json
{ "type": "done", "conversationId": "123", "messageId": "456", "fullContent": "你好，有什么可以帮你？" }
```

服务端→客户端（错误）：
```json
{ "type": "error", "conversationId": "123", "message": "DeepSeek API 调用失败" }
```

## 6. 部署架构

```
docker compose up -d
┌─────────────────────────────────────────┐
│  Docker Network: nestjs-net             │
│  ┌──────────────┐    ┌──────────────┐   │
│  │  backend     │    │  frontend    │   │
│  │  :8089       │───▶│  :5183       │   │
│  │  node:20     │    │  nginx       │   │
│  └──────┬───────┘    └──────────────┘   │
│         │                                │
└─────────┼────────────────────────────────┘
          │ TCP
          ▼
  共用基础设施（本机已起，不在本 compose 里）
  ├─ MySQL  :3310  (database=nestjs_workbench)
  └─ Redis  :6379  (db=6)
```

- **backend Dockerfile**：`node:20-alpine` → COPY package.json → pnpm install → COPY src → pnpm build → CMD `node dist/main.js`
- **frontend Dockerfile**：`node:20-alpine` build → `nginx:alpine` 拷贝 dist/ 到 /usr/share/nginx/html，nginx.conf 代理 /api 和 /ws 到 backend:8089
- **环境变量**（.env）：
  - `PORT=8089`
  - `DB_HOST=host.docker.internal`（连本机共用 MySQL）
  - `DB_PORT=3310`
  - `DB_USER=root`
  - `DB_PASS=root123`
  - `DB_NAME=nestjs_workbench`
  - `REDIS_HOST=host.docker.internal`
  - `REDIS_PORT=6379`
  - `REDIS_DB=6`
  - `JWT_SECRET=<随机32位>`
  - `JWT_EXPIRES_IN=2h`
  - `DEEPSEEK_API_KEY=<用户自己填>`
  - `DEEPSEEK_BASE_URL=https://api.deepseek.com`
  - `DEEPSEEK_MODEL=deepseek-chat`
- **环境划分**：只有 dev/prod 两套，dev 用 pnpm dev 起 Vite+Nest dev server，prod 用 Docker Compose
- **不做高可用/扩缩容**：作品集单机部署，不需要

## 7. 监控与运维

- **日志**：NestJS 内置 Logger，按 Module 分级（log/error/warn）；WS 连接/断开/异常都打日志
- **健康检查**：`GET /health` 返回 `{status:"ok", uptime: process.uptime()}`，Docker HEALTHCHECK 每 30s curl 一次
- **运维流程**：
  1. 启动前 `env_preflight.py --project nestjs-agent-workbench` 检查端口/MySQL/Redis
  2. `docker compose up -d` 起前后端
  3. `docker compose logs -f backend` 看日志
- **不做**：Prometheus/Grafana/Sentry（作品集不需要，加了是过度设计）

| 风险 | 影响 | 应对 |
|---|---|---|
| DeepSeek API Key 未配置/余额不足 | M3 流式对话无法演示 | 启动时 env_preflight 检查 DEEPSEEK_API_KEY 非空；开发阶段允许 Mock（带 `# MOCK:` 标记），交付前必须真调 |
| WebSocket 流式 chunk 在代理层缓冲 | 前端看不到逐字效果，整段一起出来 | Nginx 配置 `proxy_buffering off` + `proxy_set_header Upgrade`/`Connection`；Docker 前端 nginx.conf 已配好 |
| bcrypt 在 Node alpine 上原生编译失败 | backend 容器起不来 | 用 `bcryptjs`（纯 JS 实现，无原生编译）替代 bcrypt，API 一致 |
| Redis JWT 黑名单过期时间与 JWT 过期时间不一致 | 登出后黑名单 key 提前过期，旧 token 复活 | 黑名单 EX 时间 = JWT expiresIn（2h=7200s），从 JWT exp 字段精确计算 |
| MySQL 共用 3310 但 database 不存在 | backend 启动连不上 | TypeORM `synchronize: true` 首次启动自动建表；database 本身需要手动 `CREATE DATABASE nestjs_workbench`（写进 README） |
| host.docker.internal 在 Linux 上不识别 | Docker 容器连不到本机 MySQL/Redis | 本开发机是 Windows/macOS，host.docker.internal 原生支持；docker-compose.yml 加 `extra_hosts: - "host.docker.internal:host-gateway"` 兜底 |
| WebSocket 连接断开后前端状态不一致 | 消息发了但没收到回包 | 前端实现指数退避重连（1s/2s/4s，最多5次），重连后重新拉消息历史 |
